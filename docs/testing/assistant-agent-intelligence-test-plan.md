# AI 助手 Agent 智能测试方案

日期：2026-07-23

适用分支：`dev-agent` 及后续包含 LangGraph Agent 工作流的版本

状态：待执行

测试对象：真实火山方舟模型 + TodoList 后端 HTTP API

---

## 1. 目标与定位

本方案是 `assistant-api-black-box-test-plan.md`（以下简称"基础方案"）的进阶补充。基础方案聚焦 API 契约正确性（96 条用例，覆盖 CRUD、时间、确认流、状态机），本方案聚焦 **Agent 的智能行为**——即 Agent 在面对真实世界复杂输入时，能否展现出：

- **自主判断**：在信息不完整时主动澄清，而非静默猜测
- **自主执行**：正确分解复合指令，维护操作间的隐式依赖
- **智能学习**：在多轮对话中积累上下文，修正理解偏差，避免重复犯错
- **鲁棒性**：面对歧义、冲突、噪音和对抗性输入时，优雅降级而非崩溃

### 1.1 与基础方案的关系

| 维度 | 基础方案 | 本方案 |
| --- | --- | --- |
| 测试粒度 | 单条 API 交互 | 多轮场景 + 复合意图 |
| 输入特征 | 结构化、明确 | 口语化、含噪音、有歧义 |
| 验证重点 | 字段正确性 | 语义理解 + 上下文推理 |
| 时间跨度 | 单次请求 | 跨多轮、跨会话 |
| Agent 行为 | CRUD 正确 | 判断、修正、学习、降级 |

### 1.2 适用范围

- 本方案所有用例均使用真实方舟模型
- 执行者应为独立测试 Agent，通过 HTTP API 驱动
- 不得以 mock 模型结果代替本方案结果
- 基础方案的环境准备、执行流程、判定准则和记录模板同样适用于本方案

## 2. 智能行为判定维度

### 2.1 自主判断（Autonomous Judgment）

Agent 应在以下场景展现判断能力：

| 能力 | 定义 | 反例 |
| --- | --- | --- |
| **信息补全识别** | 识别输入中缺少的关键信息并主动询问 | 缺时间就填 `00:00`、缺分类就填 `other` |
| **歧义消解** | 当存在多种合理解读时，选择最可能的一种或主动澄清 | 静默选一个，不告知用户 |
| **冲突检测** | 识别输入内部的逻辑矛盾并指出 | 静默执行其中一种而丢弃另一种 |
| **能力边界认知** | 知道 TodoList 只能创建待办，不能真的订票/发消息 | 声称"已订票成功" |
| **优先级推断** | 从语义推断合理的优先级和分类 | 所有任务统一 medium/other |

### 2.2 自主执行（Autonomous Execution）

| 能力 | 定义 | 反例 |
| --- | --- | --- |
| **复合指令分解** | 一句中包含新增+修改+删除时，正确拆分 | 全部当新增，或只处理第一个动词 |
| **隐式关系维护** | "把会议改到明天，同时提醒小王"中，识别"会议"是同一实体 | 为"提醒小王"新建无关任务 |
| **批量操作一致性** | 多项操作在同一批次内保持原子语义 | 部分成功时静默丢弃失败项 |
| **时间链推理** | "8点起床、9点开会、会后打电话"→ 推断打电话的大致时间 | 打电话时间随意设 |
| **操作顺序感知** | 理解"先…再…然后…"的时间顺序语义 | 所有任务设为同一时间 |

### 2.3 智能学习（Intelligent Learning）

| 能力 | 定义 | 反例 |
| --- | --- | --- |
| **上下文修正** | 用户说"不对，改成四点"，Agent 理解修正的是刚提到的任务 | 新建一个四点任务 |
| **代词追踪** | 跨轮正确解析"它""那个""刚才的" | 每次都要用户重复完整任务名 |
| **偏好积累** | 多轮交互后适应用户的表达习惯 | 每轮都像第一次对话 |
| **错误恢复** | 被指出错误后，下一轮不再犯同类错误 | 重复同样的时间解析错误 |
| **隐式确认** | 修正某项时不丢失同批其他 pending 项 | 取代旧批次时丢弃 sibling |

## 4. S0: 现实场景模拟（20 条）

这些用例模拟真实用户在日常工作和生活中的完整交互序列。每条用例是一个多轮对话场景。

### S0-001: 出差规划

```
【场景】用户需要规划一次从北京到上海的出差
【前置】空数据集
【对话】
  轮1: "我下周三要去上海出差三天，帮我安排一下。需要订机票、订酒店、准备汇报材料。"
  轮2: "对了，周三上午的飞机，大概9点到虹桥。"
  轮3: "酒店订在静安寺附近，另外还需要拜访客户张总。"
  轮4: "把订机票改成'确认机票行程单'吧，机票已经买好了。"

【预期智能行为】
  - 轮1: 生成3个create待办（订机票、订酒店、准备汇报材料），时间均为下周三；对于缺乏具体时间的项目，询问或标注日期在备注
  - 轮2: 更新"订机票"的时间为下周三09:00；合理推断航班相关
  - 轮3: 新增"拜访客户张总"；酒店备注补充"静安寺附近"
  - 轮4: 将"订机票"改名为"确认机票行程单"
  - Agent 不得声称"已订好机票/酒店"
  - 所有上海、静安寺、张总等关键信息不得丢失

【验证点】复合指令分解、渐进细化、上下文修正、现实动作边界
```

### S0-002: 每日日程管理

```
【场景】用户口述一天的安排，Agent 需要正确拆分时间段
【前置】空数据集
【对话】
  轮1: "明天7点起床，7点半吃早饭，8点出门，9点到公司，9点半开早会，
        12点午饭，下午2点见客户，6点下班，7点健身房，10点睡觉。"
  轮2: "早会和见客户都标记为工作、高优先级。"
  轮3: "健身房改成晚上8点，前面加一个'晚饭'在7点。"

【预期智能行为】
  - 轮1: 生成10个独立任务，每个时间正确，end均为null（除非明确时间段）
  - 轮2: 仅更新"早会"和"见客户"的priority和category，不动其他8个任务
  - 轮3: 更新"健身房"时间、新增"晚饭"；不丢失也不改动其他任务
  - "明天"相对于requestSentAt的Asia/Shanghai日期

【验证点】大批量创建、选择性更新、时间链连续性、字段归属
```

### S0-003: 项目管理

```
【场景】用户管理一个软件项目
【前置】空数据集
【对话】
  轮1: "这个sprint我们要做用户登录、权限管理、数据库优化。登录是最优先的，
        权限管理依赖登录做完才能开始。数据库优化是技术债务，优先级中。"

【预期智能行为】

  - 轮2: 理解"登录"已存在→新增"登录前端""登录后端"（若理解"分两部分"为两个任务），或update原任务拆分
  - 轮3: 删除正确目标，权限管理备注完整保留"RBAC模型"和"设计文档v2"
  - 轮4: 查询模式，只列出没有time_start的任务，不生成proposal

```

## 5. S1: 复合意图与隐式依赖（15 条）

### S1-001: 一句三操作（增+改+删）

```
【输入】"新建一个'周报'，把'日报'改成'每日总结'，删掉'临时备忘'。"
【前置】任务"日报" medium/work; 任务"临时备忘" low/other
【预期】
  - 1个create+update批次（含"周报"create和"日报"update）
  - 1个独立delete批次（含"临时备忘"delete）
  - 三个action的目标和字段均正确
  - 确认前/beforeSnapshot一致
```

### S1-002: 隐式依赖链

```
【输入】"先整理数据，然后基于数据写分析报告，最后给老板发邮件约时间讨论。"
【前置】空数据集
【预期】
  - 生成3个任务
  - 标题保留"整理数据""写分析报告""发邮件约讨论"
  - 若模型推断时间顺序，"整理数据"时间最早、"约讨论"最晚
  - 备注或标题中保留"基于数据"和"给老板"的上下文
  - 不声称"已发送邮件"
```

### S1-003: 条件操作

```
【输入】"如果明天不下雨，就去爬山；如果下雨，就在家看书。"
【前置】空数据集
【预期】
  - 在系统不支持条件任务时，Agent应：
    1. 创建两个任务并备注天气条件，或
    2. 询问用户是否可以简化为单一任务，或
    3. 说明能力限制
  - 不得静默丢弃其中一个分支

## 7. S3: 多轮上下文推理（15 条）

### S3-001: 渐进式任务描述

```
【场景】用户在多轮中逐步细化同一个任务
【对话】
  轮1: "帮我记一个任务。"
  轮2: "关于下周的。"
  轮3: "对，下周二的。"
  轮4: "下午。"
  轮5: "3点吧。是要做季度汇报的PPT。"

【预期】
  - 轮1-4均应CL（信息不全）
  - 轮5信息足够，生成create："做季度汇报PPT", 下周二15:00
  - 五轮构建一个完整任务，代理需跨轮积累信息
  - 若任一轮猜测了不完整信息，后续须能覆盖修正
```

### S3-002: 否定式修正

```
【场景】用户连续否定来缩小范围
【对话】
  轮1: "下周有个任务。"
  轮2: "不是工作，是生活。"
  轮3: "也不是生活，是学习——报了一个在线课程。"
  轮4: "时间不是下周，是这个月底。"

【预期】
  - 每次否定应覆盖前一轮的不正确信息
  - 最终任务：category=study，"报在线课程"，月底
  - Agent不得在新任务中保留"工作"或"生活"分类
  - 旧pending应被supersede而非堆积
```

### S3-003: 代词链

```
【场景】连续使用代词引用
【对话】

  轮2: "把它提前一周。"
  轮3: "它的备注也要改，加上'需要CFO签字'。"
  轮4: "对了，它的优先级呢？"
  轮5: "也改成最高吧。"

【预期】
  - 每轮"它"都指向"Q2财务报告"
  - 轮2: update time_start
  - 轮3: update notes追加"需要CFO签字"
  - 轮4: 查询回复当前priority
  - 轮5: update priority→high
  - 不创建新任务，不误指其他任务
```

### S3-004: 话题切换与回溯

  轮3: "不对，买菜还是改回中优先级。"
  轮4: "刚才说写报告改到明天，具体几点？"

【预期】

  - 轮3: 买菜改回medium
  - 轮4: 查询回复当前时间，不应生成proposal

### S3-005: 隐式确认修正

### S3-010: 中断与恢复

```
【场景】用户在对话中插入无关话题
【对话】

  轮2: "哦对了，今天天气怎么样？"
  轮3: "回到正题，Q3规划备注加上'参考Q2数据'。"

## 11. S7: Agent 学习与适应（10 条）

### S7-001: 用户偏好学习——分类

```
【场景】用户反复将某类任务设为特定分类，Agent是否学会？
【对话】
  轮1: "新建'写代码'。"
  轮2: "不对，这个应该是工作类。"
  轮3: "新建'调试bug'。"
  轮4: "也是工作类。"
  轮5: "新建'重构模块'。"

【预期】
  - 轮5：Agent如能从历史中学到"代码相关→work"，应在轮5自动设为work（加分项）
  - 如轮5仍为other（默认），不算失败但说明无学习能力
  - 核心：观察Agent在同类任务的第3次是否开始推断
```

### S7-002: 用户偏好学习——时间

```
【场景】用户倾向于在下午安排会议类任务
【对话】
  轮1: "明天有个项目会，下午3点。"
  轮2: "后天有客户演示，也是3点吧。"
  轮3: "对了，下周一也有一个评审，还是下午？"
  轮4: "加个代码走查。"

【预期】
  - 轮3虽用疑问句，但Agent可推断用户倾向下午3点
  - 轮4"代码走查"是不同类任务，Agent不一定推断下午时间
  - 核心：会议类任务的时间模式是否被Agent捕捉
```

### S7-003: 错误模式识别与避免

```
【场景】Agent在时间解析上的错误被纠正后应避免
【对话】
  [前置：在某天下午16:00执行测试]
  轮1: "今天下午3点开会。" [Agent若在16:00遇到"下午3点"——已过期]
  [Agent CL是否指明天]
  轮2: "哦对，已经过了，那就明天下午3点吧。"
  轮3: "今天下午2点还有一个培训。" [同样的情况]

【预期】
  - 轮3: Agent应意识到今天14:00也已过（在16:00执行时）
  - 主动CL或建议明天
  - 不应在轮3重犯同样的忽视过去时间错误
```

### S7-004: 命名风格适应

```
【场景】用户偏好使用英文命名工作任务
【对话】
  轮1: "新建'Q3 Planning Meeting'。"
  轮2: "再加'Sprint Review'和'1on1 with Manager'。"
  轮3: "帮我把明天的'standup'也建一下。"
  轮4: "查一下meeting相关的任务。"

【预期】
  - 中英混用场景正常处理
  - 轮4的查询"meeting相关"应该匹配英文标题中的"Meeting"
  - Agent不得把英文标题强制翻译为中文
```

### S7-005: 简洁vs详细偏好

```
【场景】用户不断简化表达，Agent是否适应用户的简洁风格
【对话】
  轮1: "帮我添加一个任务，标题是'明天上午10点去银行办理外汇业务'，分类为生活。"
  轮2: "下午3点，理发。生活。"
  轮3: "后天，超市。"
  轮4: "大后天，医院。"

【预期】
  - 轮2-4的极简表达应被Agent正确理解
  - 轮3"后天，超市"→新建"去超市"或"超市购物"，D0+2，life（继承偏好）
  - 轮4"大后天，医院"→同理
  - Agent适应了用户的极简风格
```

### S7-006: 术语消歧学习

```
【场景】用户使用组织内部术语
【对话】
  轮1: "建一个'QBR'任务。"
  [Agent CL: "请问QBR是什么？"]
  轮2: "QBR是Quarterly Business Review，季度业务回顾。"
  轮3: "QBR定在8月15日。"
  轮4: "QBR需要准备的数据，也建个任务。"

【预期】
  - 轮3和轮4中Agent理解QBR=季度业务回顾
  - 轮4创建的关联任务，合理关联到QBR
```

### S7-007: 拒绝模式学习

```
【场景】用户多次拒绝某类Agent建议，Agent是否停止该类建议
【对话】
  轮1: "新建'跑步'。" [Agent可能询问时间]
  轮2: "不需要时间。"
  轮3: "新建'游泳'。" [Agent不应再次询问是否需要时间]
  轮4: "新建'骑车'。"

【预期】
  - 轮3中Agent不再次强制询问时间（已从轮2中学习用户对运动类任务不设时间）
  - 轮4同理
  - 但Agent如不确定，温和询问比静默假设更好
```

### S7-008: 多用户角色切换（模拟）

```
【场景】同会话中，用户切换身份
【对话】
  轮1: "帮我（项目经理）建一个'项目启动会'，明天。"
  轮2: "对了，切换到开发视角，加一个'搭建开发环境'。"
  轮3: "回到项目经理，启动会需要准备议程。"

【预期】
  - 轮2创建"搭建开发环境"（可能属于work/study）
  - 轮3"启动会"指轮1创建的任务（正确关联）
  - 身份切换不应导致上下文丢失
```

### S7-009: 渐进式指令学习

```
【场景】用户逐步教Agent自己的命名规范
【对话】
  轮1: "新建'[工作] 周报'。"
  轮2: "以后工作类的任务前面都加[工作]。"
  轮3: "新建'项目评审'。"
  轮4: "周报写完了，改成已完成。还有，加一个'需求讨论'。"

【预期】
  - 轮3：Agent可能（加分项）按轮2要求自动加[工作]前缀
  - 允许Agent未自动添加（"以后"规则的遵循需要agent持久化偏好，当前系统无此能力）
  - 若不支持，Agent应说明限制
```

### S7-010: 零样本到少样本适应

```
【场景】前几个任务给了详细例子，后面类似任务只需关键词
【对话】
  轮1: "新建'客户A合同评审'，工作，高优先级，8月20日下午2点。"
  轮2: "客户B也一样的，但是8月21日。"
  轮3: "客户C，8月22日。"

【预期】
  - 轮2: create '客户B合同评审' work/high 2026-08-21T14:00（继承轮1的模式）
  - 轮3: create '客户C合同评审' work/high 2026-08-22T14:00
  - Agent应在零样本提示下学习任务模板
```

## 12. 判定矩阵

### 12.1 智能等级评定

每条用例除 PASS/FAIL 外，还需标注智能等级：

| 等级 | 定义 | 说明 |
| --- | --- | --- |
| **L0** | 基础正确 | CRUD操作字段正确，满足基础方案Oracle |
| **L1** | 合理处理 | 对歧义/缺失信息能CL，不静默猜测 |
| **L2** | 智能推断 | 基于上下文进行合理推断，推断正确率高 |
| **L3** | 主动学习 | 在多轮中展现模式学习和行为适应 |

每类场景的及格线：
- S0（现实场景）: 至少L1
- S1（复合意图）: 至少L0
- S2（歧义消解）: 至少L1
- S3（多轮推理）: 至少L1
- S4（时间边界）: 至少L0
- S5（压力测试）: 不崩溃即为L0
- S6（跨会话）: 至少L0
- S7（学习适应）: 观察到L2/L3为加分

### 12.2 严重等级（沿用基础方案）

| 等级 | 定义 | 本方案额外说明 |
| --- | --- | --- |
| S0 阻断 | 不可接受的核心错误 | 声称"已订票/已发邮件"等现实动作；跨会话误操作；数据丢失 |
| S1 严重 | 语义/目标错误 | 歧义时静默选错；复合指令丢失操作；代词指错对象 |
| S2 一般 | 次要错误 | 该CL时猜测但猜错；优先级/分类不合理；批次数不合理 |
| S3 轻微 | 不影响数据 | 回复冗长；未主动利用学习机会；推断不够但数据正确 |

## 附录B: 已知限制与未来扩展
