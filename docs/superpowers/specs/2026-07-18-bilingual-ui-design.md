# TodoList 中英文界面切换设计

日期：2026-07-18
目标版本：v1.0.0（不修改版本号）

## 1. 目标

为 TodoList 增加中文与英文界面切换。语言按钮位于首页顶部右侧操作区，中文界面显示 `EN`，英文界面显示 `中文`。切换后，应用提供的可见文字、日期显示、通知、错误提示和无障碍标签全部使用所选语言。

当前中文文案和视觉样式保持不变。英文只替换文案和日期格式，不重新设计布局。用户输入的任务标题与备注保持原文，不做自动翻译。

## 2. 已确认约束

- 支持 `zh-CN` 与 `en` 两种语言。
- 默认语言为 `zh-CN`。
- 语言偏好写入 SQLite，应用重启后保持上次选择。
- 不使用 `localStorage` 或第二套持久化数据源。
- 英文日期使用 `en-US` 格式；中文沿用当前中文表达。
- 所有应用自带文案均纳入翻译范围，包括系统通知与 `aria-label`。
- 应用版本继续为 `1.0.0`。
- 功能完成后重建安装包，移动公开的 `v1.0.0` 标签并替换 GitHub Release 资产，同时更新 Notion 文档。

## 3. 方案选择

采用项目内轻量、类型安全的国际化层，不引入第三方运行时依赖。

未采用的方案：

- 通过 props 从 `App` 逐层传递翻译对象：会扩大大量组件接口并产生无意义的 prop drilling。
- 引入 `react-i18next`：适合多语言包、异步加载和复杂复数规则，但对当前仅中英文的范围过重。

## 4. 前端架构

新增 `frontend/src/features/i18n/`，职责如下：

- `translations.ts`：定义中文基准词典、英文词典和翻译键类型。
- `I18nProvider.tsx`：向组件提供 `language`、`locale`、`t()` 和语言切换入口。
- `useLanguage.ts`：管理数据库优先的语言更新，与现有 `useTheme` 的提交语义一致。

词典由同一类型约束。中文词典作为当前文案基准，英文词典必须具有完全相同的键；缺失键在 TypeScript 编译期失败。

Provider 设置根元素的 `lang` 属性：

- 中文：`<html lang="zh-CN">`
- 英文：`<html lang="en">`

组件通过 `useI18n()` 获取文案，不接收翻译 props。稳定业务值继续使用现有 ID，例如分类 `work`、优先级 `high`、成就 `first-task`；词典只负责把 ID 映射为界面文案。

## 5. 语言状态与数据流

bootstrap 的 `settings` 增加 `language`。正常启动流程：

1. 应用以中文作为冷启动默认语言。
2. Tauri 启动 Python sidecar。
3. bootstrap 从 SQLite 返回 `settings.language`。
4. Provider 同步为数据库语言并渲染完整界面。
5. 用户点击顶部语言按钮。
6. 前端调用 `PATCH /api/v1/settings` 保存目标语言。
7. 只有后端成功返回后，Provider 才发布新语言状态并更新整个界面。

保存失败时保持原语言，并显示原语言对应的错误提示。发生运行期基础设施故障时，阻断页保留当前进程最近一次成功加载的语言。

冷启动期间尚未读到 SQLite 设置，因此加载提示和 bootstrap 前错误默认使用中文。这是坚持 SQLite 单一数据源的明确取舍；不为消除短暂中文提示而增加 `localStorage`。

## 6. 后端与数据库

后端模型新增：

- `Language = Literal["zh-CN", "en"]`
- `AppSettings.language`
- `SettingsPatchCommand.language`

前端 API contract 同步增加同名字段。

新增迁移 `backend/migrations/002_add_language_setting.sql`：

- 为 `app_settings` 增加非空 `language` 列。
- 默认值为 `zh-CN`。
- 通过 SQLite `CHECK` 限制为 `zh-CN` 或 `en`。

不修改已经发布的 `001_initial.sql`。现有数据库升级后自动获得中文默认值；新数据库按顺序执行 `001` 和 `002`。

`SettingsRepository` 负责读取和更新语言。更新继续使用现有 settings 事务，不新增 API 路由。

## 7. 翻译范围

词典覆盖以下第一方内容：

- 顶部栏、语言按钮、音效、成就和设置入口。
- 侧栏分类、状态筛选、搜索与今日进度。
- 任务列表排序、时间分组、时间轴和空状态。
- 创建任务、任务详情、删除确认和清除完成任务。
- 时间选择器的月份、星期、模式、按钮和标签。
- 设置页、主题名称、主题说明、快捷键与自启动。
- 成就名称、成就说明、解锁提示和统计标签。
- 提醒通知、操作反馈、启动页、阻断页与重试按钮。
- placeholder、`title`、`aria-label` 和屏幕阅读器状态文本。

用户任务标题和备注不翻译。快捷键符号、产品名 `Todo List`、数字、用户数据和技术标识保持原值。

## 8. 日期与动态文案

日期和时间格式集中通过国际化层处理，组件不自行拼接中文月份或星期：

- 中文使用 `zh-CN`。
- 英文使用 `en-US`。
- 时间范围继续显示开始与结束时间。

数量、任务名和日期等动态值通过翻译函数参数插值。英文文案允许自然语序，不通过字符串替换中文片段生成。

成就定义按稳定 ID 保存，名称和说明在渲染时本地化。提醒通知标题与操作反馈同样在触发时读取当前语言。

## 9. 错误处理

后端继续返回稳定错误码，不根据语言生成响应。

前端按错误码选择本地化文案：

- 已知业务错误映射到对应中英文提示。
- 网络、超时、无效响应和数据库不可用使用对应语言的统一提示。
- 未知错误显示当前语言的通用错误，不直接暴露后端原始消息。

语言写入失败不进行乐观切换。后端模型校验和 SQLite `CHECK` 共同拒绝不支持的语言值。

## 10. UI 约束

语言按钮放入 `Header` 右侧操作区，紧邻音效按钮并复用现有按钮视觉语言：

- 中文界面显示 `EN`。
- 英文界面显示 `中文`。
- `title` 和 `aria-label` 描述切换目标语言。

不修改现有主题、颜色、三栏布局或中文样式。英文文本较长时使用现有弹性布局与必要换行，不引入单独的“英文主题”或复制 CSS。

- 默认中文渲染保持现状。
