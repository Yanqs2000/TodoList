# v0.4.1 — 设置面板整合 + 热键修复（2026-06-19）

## 概览

修复 v0.4.0 的几个问题，并将主题切换合入设置面板。

## 修复

### 🔴 全局热键无法录制
**问题**：v0.4.0 的快捷键录制使用 React onKeyDown，按下 Cmd+T 等组合时浏览器/操作系统先消费按键事件（`new tab`/Tauri 默认菜单等），到不了 React 合成事件层。结果是按下任何键都没反应。

**修复**：改用 `document.addEventListener('keydown', ..., true)` capture-phase 监听。在录制状态下 `e.preventDefault() + e.stopPropagation()` 抢在浏览器之前。同时录制按钮的 onKeyDown 完全移除（不再需要）。

### 🔴 Mac 没有 Alt 键
**问题**：v0.4.0 默认热键 `Alt+Space`，UI 显示 `Alt+Space`，Mac 用户找不到 Alt 键。

**修复**：
- **默认热键改为 `Cmd+Option+T`**（Tauri 字符串 `Cmd+Alt+KeyT`，跨平台等价于 macOS 的 ⌘⌥T / Win+Linux 的 Ctrl+Alt+T 概念）
- UI 显示按平台格式化：macOS 显示 **⌘⌥T**，Win/Linux 显示 **Ctrl+Alt+T**
- 描述加注「macOS 的 Option = ⌥」帮助理解

### 🟡 主题切换分散
**问题**：v0.4.0 主题选择是独立 popover（Header 月亮按钮），现在又有了齿轮图标的设置面板，两处设置入口混乱。

**修复**：
- 删除 Header 的主题切换按钮和独立 ThemeSwitcher 组件
- 在「设置」面板顶部加入主题选择网格（6 卡片，与 v0.2.0 ThemeSwitcher 一致的视觉但内嵌）
- 删除 `src/features/theme/components/ThemeSwitcher.tsx` 及其样式（死代码）

## 实现细节

### 热键 accelerator 格式
现在生成的 accelerator 字符串总是带显式 Code 前缀（`Cmd+Alt+KeyT` 而不是 `Cmd+Alt+T`），更明确不易歧义。global-hotkey 的 parser 同时接受两种形式所以兼容旧值。

### Mac 平台显示
`formatShortcut()` 检测 `navigator.platform` 区分 macOS / 其他系统：
- macOS：`Cmd+Alt+KeyT` → **⌘⌥T**
- Win/Linux：`Cmd+Alt+KeyT` → **Win+Alt+T**
- KeyT/Digit1 等显示前缀自动剥离

### Settings 面板新结构
```
设置 Modal
├── 外观主题
│   └── 6 卡片网格（点击即刻切换）
└── 桌面
    ├── 全局快捷键（录制 + 应用 + 恢复默认）
    └── 开机自动启动
```
