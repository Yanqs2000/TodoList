# v0.4.3 — 修复无分类任务无法在分类筛选中找到（2026-06-19）

## 问题

用户反馈：创建任务时如果没有指定类别，任务只能在「全部」里看到，点任何一个具体分类（工作/学习/生活/其他）都找不到它。

## 根因

`CreateTaskModal` 的 `category` state 初始值是 `undefined`，用户不选分类直接提交，任务存进 localStorage 的 `category` 字段就是 `undefined`。

而 `useTodos` 的分类筛选逻辑是 `if (categoryFilter !== 'all' && t.category !== categoryFilter)`——`undefined !== 'work'` 恒成立，所以无分类任务被所有具体分类筛选排除掉，只在 `categoryFilter === 'all'` 时可见。

## 修复

**三层兜底，保证无分类任务一律归到「其他」**：

### 1. 创建任务时（`useTodos.addTask`）
```ts
category: category ?? 'other',  // 调用方没传就默认 'other'
```
这是最根本的兜底——无论从哪个入口创建（模态、未来 API、测试），无 category 一律归 'other'。

### 2. 模态 UI 默认值（`CreateTaskModal`）
`category` state 初始值从 `undefined` 改为 `'other'`，4 个分类按钮里「其他」默认高亮。用户没改动就提交 → 明确是「其他」。

### 3. 存量数据迁移（`loadInitialTasks`）
升级用户已有的任务可能 `category` 是 `undefined`。加载时归一化：
```ts
return validateTodoArray(parsed).map(t => (t.category ? t : { ...t, category: 'other' }));
```
下次启动后旧任务也能在「其他」分类下找到。

## 测试

新增 2 个用例：
- 新建任务不传 category → `category === 'other'`，且在「其他」筛选下可见
- localStorage 中存有无 category 的遗留任务 → 加载后归一为 'other'，「其他」筛选可见
